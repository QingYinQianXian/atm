# ATM 柜员机模拟程序 - 软件工程期末项目

这是一个采用 Python 3 开发的 ATM 模拟系统，严格遵循 **MVC (Model-View-Controller)** 设计模式，旨在实现业务逻辑与界面的深度解耦。

## 一、 系统架构原理 (MVC 模式)

为了符合软件工程的高内聚、低耦合要求，本项目划分为三个层次：

### 1. 模型层 (Model) - `models.py`
*   **职责**：管理核心数据和业务规则。
*   **原理**：封装了与 `data.json` 的交互逻辑。所有的业务判定（如取款是否为100倍数、密码是否符合强度、余额是否足够）均在此层完成。完全不关心界面是如何显示的。

### 2. 视图层 (View) - `views.py`
*   **职责**：负责图形界面的布局与呈现。
*   **原理**：基于 `Tkinter` 构建。只负责将数据展示给用户，并将用户的点击或输入动作传递给控制器。不包含任何业务逻辑判断。

### 3. 控制层 (Controller) - `controllers.py`
*   **职责**：逻辑调度与中转。
*   **原理**：作为 Model 和 View 的桥梁。当用户在 View 点击操作按钮时，Controller 获取输入并交给 Model 处理，处理完后，Controller 指令 View 弹出成功提示或报错信息。

## 三、 业务逻辑规则限制

### 1. 取款 (Withdraw)
*   金额必须是 100 的整数倍。
*   单次取款不得超过 5000 元。
*   账户不可透支。

### 2. 存款 (Deposit)
*   金额不可为负数。

### 3. 转账 (Transfer)
*   金额必须大于 0。
*   目标账户必须存在。
*   不能转账给自己。
*   账户不可透支。
*   转账双方均记录交易日志（转出方记"转出"，收款方记"转入"）。

### 4. 修改密码 (Change Password)
*   旧密码必须验证通过。
*   新密码长度需 ≥ 6 位。
*   新密码不能是完全相同的字符（如 `111111`、`aaaaaa`）。
*   两次输入的新密码必须完全一致。
*   修改成功后强制重新登录。

### 5. 注册新账户 (Register)
*   系统自动生成账号（当前最大账号号 +1）。
*   密码规则与修改密码一致：长度 ≥ 6 位，不允许完全相同的字符。
*   两次输入的密码必须一致。
*   初始余额为 0 元。

### 6. 交易明细 (Transaction History)
*   每笔存款、取款、转账操作自动记录日志。
*   日志内容包含：类型、金额、时间、操作后余额、对方账户。
*   通过「交易明细」界面以表格形式查看。

### 7. 账户锁定 (Account Lockout)
*   同一账户连续 3 次密码输入错误，自动锁定 **5 分钟**。
*   锁定期间登录会提示精确到秒的剩余时间。
*   锁定时间到期后自动解除，失败计数清零。

## 六、 如何运行

### 1. 环境准备
*   确保安装了 Python 3.6+。
*   在 Linux 系统上，若缺失 Tkinter，请运行：`sudo apt-get install python3-tk`。

### 2. 运行步骤
1.  **创建并激活虚拟环境**：
    ```bash
    python3 -m venv venv
    source venv/bin/activate  # Linux/Mac
    # Windows: venv\Scripts\activate
    ```
2.  **启动程序**：
    ```bash
    python3 main.py
    ```

> **注意**：由于本项目是 GUI 程序，必须在拥有桌面环境（Windows/macOS/Linux Desktop）的机器上运行。在纯命令行（如 SSH 远程服务器）中运行会报 `TclError: no display name` 错误。
